### Late correction (the more valuable half)

Rather than declare victory after the restart, I watched the probe run for half
an hour. It was wrong twice. The 45s timeout sat *inside* the healthy spread
(successes at 13.3s, 19.9s, 21.2s, 32.5s, 36.6s interleaved with 45s timeouts),
so it kept reaching its restart condition on a merely-slow gateway. And the
upstream guard used `/v1/models`, far too weak to discriminate: **vllm-chat runs
`max_num_seqs=1` and Bifrost's `vllm-local` lane is `concurrency=1`**, so one
long generation legitimately owns the lane — a **651-second** completion was
logged from ada-backend while vLLM healthily produced 54 tok/s. `/v1/models`
answers instantly throughout, so the old guard would have restarted
mid-generation and aborted real work.

So the recurring stall is **capacity, not a leak**. `vllm-local` is the only lane
at concurrency=1 (embed-local 8, nvidia-nim 16, the rest 4). A restart clears the
queue and buys about fifteen minutes, which is exactly the pattern both prior
incident records show. The probe now defaults to `ACTION=alert`: detection was
the genuinely missing capability and is safe; auto-restarting a capacity problem
trades real in-flight work for fifteen minutes.

## Key Lesson

"Is the tree dirty?" and "does HEAD build?" are different questions, and only the
second one matters. `git status` tells you a tree is dirty; it cannot tell you the
committed state is broken. Seven consecutive runs read the porcelain output,
classified it as operator WIP, and moved on. The probe that settles it is three
commands and about twenty seconds.

Second lesson, now a three-run pattern: a probe that always passes is worse than
no probe. The first version of the completion probe used a bare model name, which
Bifrost rejects with a 400 that the probe correctly scores as "responsive" — it
would have passed forever without exercising a completion. Same shape as the
12k diff truncation and the discarded `runtime_evidence` in previous runs.
Whenever you build something that watches something else, ask what it does when
its own input is malformed, and make that case loud.
